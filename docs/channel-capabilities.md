# 设备通道能力管理标准

## 权威来源

`DeviceDriver::capabilities(device_id)` → `DeviceRegistry` → Tauri `device_capabilities` → 前端 `HardwareCaptureCapabilities`。
前端不得按厂商名称、USB ID、设备标题推断通道类型或通道数量。浏览器预览也必须提供相同契约。

| 字段 | 语义 |
| --- | --- |
| `max_channels` | 数字输入总上限（当前 packed 数字采集链路支持 1–32 路） |
| `channel_modes[].channels` | 对应 Stream/Buffer 模式的数字通道上限，不能突破 `max_channels` |
| `sample_rates` / `channel_modes[].sample_rates` | 数字采样率及模式约束 |
| `max_analog_channels` | 可用模拟输入数，0 表示不支持；不是电平阈值设置或 PWM 输出数 |
| `analog_sample_rates` | 模拟输入支持的正整数 Hz 列表；纯数字设备必须返回空列表 |

模拟字段在 Rust 序列化中总是输出；反序列化旧数据时默认 0 / []。前端兼容旧后端缺失字段，同样按不支持处理，不回退到 Demo 的 16 路或采样率列表。

## 当前声明

| 来源 | 数字上限 | 模拟上限 |
| --- | --- | --- |
| PXLogic | 从实际 profile/channel modes 解析，最大 32 | 0 |
| Kingst LA2016 | 从型号解析，16（其他 Kingst 型号使用各自上限） | 0 |
| Demo | 32 | 16（前端合成信号，默认启用 4 路） |

## 前端规则

1. 能力尚未加载时，不展示猜测的通道选择器，禁止启动采集并提示刷新设备。
2. 数字选择器受设备总上限和模式上限共同约束；采集设置在能力返回、切换设备和启动采集时裁剪。
3. 模拟通道数组按能力创建/裁剪；复制设置必须保留数组长度，空数组不能补成 Demo 通道。
4. 设备切换不继承另一台设备的模拟启用状态；同设备会话复制保留有效设置。
5. 模拟上限为 0 时，不渲染模拟配置块、模拟采样率和模拟波形行。渲染时再次按能力过滤，避免旧状态短暂泄漏。
6. 模拟采样率只来自声明列表，去重、过滤无效值并排序。列表为空时禁用选择器；无模拟能力时状态采样率归零。
7. 已有数字采集数据/导入文件的通道元数据保持不变；只读导入会话不执行硬件能力归一化。可写会话切换设备后，下一次采集配置按新设备收敛。

## 新设备接入清单

- 在驱动中基于识别到的实际型号构造能力，不使用通用 32 路作为硬件识别失败的替代值。
- 纯数字设备显式填 `max_analog_channels: 0`、`analog_sample_rates: Vec::new()`。
- 模拟能力必须代表已实现的功能。当前真实硬件 ADC 数据通路尚未实现，不能只填非零字段就宣称支持模拟采集；未来需同时接入采样数据、存储和渲染，不能用 Demo 波形冒充硬件数据。
- 添加型号能力测试以及前端通道数、设备切换和空能力回归测试。无需在前端新增厂商判断。

## 验证

- `node --test tests/*.test.ts`
- `pnpm exec tsc --noEmit`
- `cargo test --workspace --locked`（现有日志测试存在共享状态并发干扰时，以 `-- --test-threads=1` 串行重跑确认）
- 实机验收：Demo → PXLogic → LA2016 切换；数字选择器分别不超过 32 / 16，两台硬件均无模拟配置及模拟波形，切回 Demo 可正常显示模拟通道。
