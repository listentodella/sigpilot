# 协议内容触发

协议触发在采集过程中检查 UART、I²C 或 SPI 通信内容，命中条件后保留指定的前后波形，并将协议事件的位置设为时间零点。判断依据是采集样点，USB 回调和界面刷新延迟不会改变触发坐标。

## 支持范围

- UART：匹配连续的 1–64 个字节；使用所选分析器的通道、波特率、反相、数据位、校验、停止位和位序设置。
- I²C：匹配 7 位地址、数据或 NACK，可限制目标地址和数据值。
- SPI：匹配 MOSI 或 MISO 上连续的 1–64 个字，使用分析器的时钟相位、极性、片选和位序设置。当前分析器界面提供 1–32 位字宽；底层触发引擎支持 1–64 位字宽。
- 支持具有明确 UART / I²C / SPI 参数的分析器配置，触发不依赖其用于显示的解码后端。任意 Native 分析器和 HLA 尚不能作为触发源。
- 软件触发只支持 **Stream / Looping** 采集模式，包括 Demo 和提供流式数据的真实设备。Buffer 模式先在设备内采集再下载，不能用于本功能。
- 软件协议触发不能同时启用硬件触发、外部触发或触发输出。

这不是 FPGA 协议触发：主机必须持续收到样本。可用采样率仍受设备、USB 传输及主机处理能力约束。

## 触发位置和保留窗口

UART 或 SPI 序列命中时，以**最后一个匹配字节/字的起点**为触发样点；I²C 以匹配的地址或数据事件起点为触发样点。只有完整事件已收到时才确认命中。

例如最后一个匹配字节从样点 1240 开始，触发前保留 200 样点、触发后保留 300 样点，最终保存范围是 `[1040, 1540)`，文件中的触发样点为 200。若配置的后段短于完整协议事件，仍保留完整事件。USB 最后一块可能包含更多数据，完成后按样点裁剪，多余数据不会进入最终结果。

完成后同时收缩样本和波形边沿索引的分配容量，释放已丢弃窗口与驱动预留空间；小片段不会继续占用等待期间的整块采集缓冲。

在等待期间，驱动仍保存已采集的样本；这是**有等待时限和内存上限的采集**，不是环形缓冲，也不支持无限期等待。触发前后窗口各最多 60 秒，等待时限为 1 毫秒至 1 小时。实际等待时间还受采集内存预算限制。

若事件出现在采集开始后很短时间内，前段历史可能不足。界面应区分以下结果：

| 状态 | 含义 |
| --- | --- |
| `matched` | 已命中并收到完整后段；前段是否完整另行报告 |
| `timed_out` | 在样本时间或实际等待时限内未命中 |
| `stopped_without_match` | 未命中时采集已停止，例如用户点击停止 |
| `buffer_limit` | 未命中且已达到采集内存上限 |
| `incomplete` | 已命中，但用户停止、内存限制或设备停流使后段不足 |

未命中时保留实际已采集的数据供检查，不创建虚假的触发标记。命中后不足的后段也保留现有数据并报告不完整。协议名称和精确触发位置保存在采集元数据中，可随 `.pxl` 保存和重新打开。

## 执行与资源边界

`sigpilot-core::protocol_trigger` 直接消费采样块，以跨块状态机检测协议，避免显示用解码列表的抽稀造成漏触发。状态机只保留当前协议状态及有界匹配序列；不会为触发复制整个采集、反复扫描历史或启动 Native 解码进程。

`sigpilot-graph::protocol_trigger_capture` 管理实际采样率、命中通知、等待期限、后段停止和最终裁剪。采集所有者负责轮询 watchdog；按采样时间严格执行等待期限，实际时钟额外允许 5 秒数据交付宽限，避免 USB 分块交付晚于短等待窗口时拒绝窗口内的有效事件。完全没有数据时也会在等待时限加 5 秒后请求停止；命中后的后段若停流超过后段时长加 5 秒宽限，也请求停止。完成后该控制器不再产生停止请求，避免影响下一次采集。

## 使用 Demo 验证

1. 在桌面创建 Demo 采集，选择 Stream / Looping 模式，并启用目标分析器使用的数字通道。
2. 添加 UART 分析器，选择 Legacy Rust 后端、D0、100000 baud、8N1、不反相、低位在先；采样率设为 1 MHz。
3. 在协议触发面板选择该 UART，输入十六进制字节序列 `64 65 6D 6F`（`demo`），前段 2 ms、后段 3 ms、等待 1000 ms。
4. 启动采集。Demo 发出 `SigPilot demo`，命中后自动停止；触发时间零点是最后一个 `6F` 字节的起点。也可用 `53 69 67` 匹配 `Sig`。
5. 保存 `.pxl` 并重新打开，确认协议触发标记和相对时间零点保留。改成 `FF` 后重新采集，可观察未命中超时状态。

I²C Demo 可用 SDA=D1、SCL=D2，选择地址 `0x20` 的 NACK，数据限定 `0x90`。SPI Demo 可用 MOSI=D3、MISO=D4、Clock=D5、Enable=D6，低电平片选、8 位、MSB first，匹配 MOSI 的 `4C`。不同分析器请避免占用相同通道。

## 验证

`cargo test -p sigpilot-graph protocol_trigger_capture -- --test-threads=1` 覆盖真实 Demo 生成与采样回调、样点准确性、前后裁剪、时间零点、`.pxl` 往返、未命中超时、手动停止、缓冲区限制和后段不足。Demo 用例的采集预算为 1 MiB。协议状态机的跨块、格式和条件测试位于 `sigpilot-core`。

2026-11-20 本机 macOS 验证记录：

- `sigpilot-core` 库测试 145 项通过，`sigpilot-file` 20 项通过，`sigpilot-graph` 115 项通过；33 项原有外部运行时 / native fixture 测试按原设置忽略。其中新增协议检测 14 项、采集生命周期 10 项。
- Desktop Rust 编译检查、TypeScript 检查及 Vite 生产构建通过。
- 协议配置及视口前端测试 15 项通过；[真实 React 面板浏览器检查](../tools/protocol-trigger-verify/README.md) 13 项通过，覆盖三种协议、无效条件、禁用状态、中英文布局及折叠状态。
- Demo UART 触发事件原始样点为 1240，裁剪后 T0 为 200，保留 500 个样点，`.pxl` 保存重开保持一致；完成后的样本及索引分配小于 64 KiB。

浏览器检查使用真实组件和明确的测试属性，采集验证使用 Rust FakeBackend；不代表完整 Tauri 窗口或真实 USB 设备的端到端测试。触发设置保留在当前会话及复制的会话中；采集文件保存命中位置和协议名称，尚不保存用于下一次采集的触发条件配置。

Demo 和单元测试不能替代实际 USB 设备的持续吞吐、丢样和停止延迟验收；硬件性能应按目标设备、启用通道数和采样率单独记录。
