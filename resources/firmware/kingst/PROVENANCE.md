# Kingst LA series firmware and FPGA bitstreams

Vendor binaries for the Kingst LA series logic analyzers, loaded by
`crates/sigpilot-core/src/kingst_la2016.rs` when a device is prepared.

## What is here

| File | Role |
| --- | --- |
| `kingst-la-<pid>.fw` | Cypress FX2LP MCU firmware, named after the USB PID. `kingst-la-01a2.fw` is the one the LA1016/LA2016 use. |
| `kingst-la<model>-fpga.bitstream` | Altera EP4CE6 FPGA bitstream, one per board revision. Selected by the EEPROM magic byte. |

The driver picks the pair from the EEPROM identification: the USB PID chooses
the `.fw`, the magic byte chooses the `.bitstream`.

## Where these came from

Extracted from the vendor's **KingstVIS** application with
[`sigrok-fwextract-kingst-la2016`](https://github.com/sigrokproject/sigrok-util)
from the sigrok-util repository:

```sh
python3 sigrok-util/firmware/kingst-la/sigrok-fwextract-kingst-la2016 KingstVIS/KingstVIS
```

KingstVIS is a free download from <https://www.qdkingst.com/en/download>.

## Licensing status — read before publishing

These are **vendor binaries with no license grant attached**. Kingst does not
publish them for redistribution; the extraction step above exists precisely
because they are not distributed with open-source tooling.

For contrast, the PXLogic assets in the sibling directory
`resources/bitstreams/` carry an explicit **MIT** `LICENSE.txt`, which is what
makes bundling those uncontroversial. Nothing equivalent exists for these files.

The reference project does **not** ship them. libsigrok's documentation requires
the user to extract the files and place them in a `sigrok-firmware` directory,
and the community keeps a *separate private repository* for the extracted
payloads specifically so the open one stays clean.

This also conflicts with this repository's own conclusion in
`docs/reuse-vs-decisions`-adjacent material — see `docs/reuse-vs-rebuild-decision.md`,
which states that redistributing extracted vendor assets has no authorization
basis.

**So: bundling these is a deliberate, owner-approved exception, not an oversight.**
If that decision is revisited, the removal is mechanical:

```sh
git rm -r --cached resources/firmware/kingst
printf '/resources/firmware/kingst/\n' >> .gitignore
```

The driver keeps working either way — it already searches
`SIGPILOT_KINGST_FIRMWARE_DIR` and the usual `sigrok-firmware` directories
before falling back to this bundled copy, so a user who extracts the files
themselves needs no change.

## Regenerating

Nothing here is generated by a build step; the files are committed as-is. To
refresh them, re-run the extraction against a current KingstVIS release and
replace the directory contents.
